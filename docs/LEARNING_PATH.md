# How we will learn

We will build one working piece at a time. You do not need to understand the full architecture before starting.

For each session I will:

- Explain the new concept in plain language and connect it to our example.
- Show and explain a small amount of code.
- Run it with you and inspect the output.
- Help you change one input or diagnose one failure.
- Ask one short question to check understanding.

We will cover Python, HTTP APIs, databases, the frontend, model calls, LangGraph, retrieval, and n8n in that order. When something is unfamiliar, we slow down and practise it before introducing the next layer.

Architecture understanding grows from answering concrete questions: where does this rule belong, what data does it need, and what happens when this call fails? Production concerns become later exercises once the local flow works.
